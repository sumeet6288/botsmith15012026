Chat Widget Flash Bug - FIXED ✅

✅ FIX APPLIED

The BotSmith chat widget was experiencing a visual "flash" on page load where default content would briefly display before being replaced with actual chatbot data. This has been fixed!

🔍 Problem Description

When the widget loaded on a webpage, users would see:

  • Initial display: "Chat Support" title with default branding
  • 100-500ms delay while API data loads
  • Sudden change to actual chatbot name and custom branding
  • Result: Jarring flash effect that looked unprofessional

✨ The Solution

We implemented a smooth loading strategy that hides the chat bubble until all data is loaded, then reveals it with an elegant fade-in animation.

❌ Before Fix

  1. Bubble appears instantly
  2. Shows "Chat Support"
  3. 100-500ms delay
  4. Content suddenly changes
  5. Flash visible to user

✅ After Fix

  1. No bubble visible initially
  2. API loads in background
  3. 100-500ms delay
  4. Bubble fades in smoothly (300ms)
  5. Professional appearance

🧪 Testing Instructions

💡 Note: The chat bubble in the bottom-right corner is a live demo. Watch it carefully on page load to see the smooth fade-in animation with no flash!

📋 Technical Details

Changes Applied:

  • Initial state: opacity: 0; visibility: hidden;
  • Smooth transition: transition: opacity 0.3s ease, visibility 0.3s ease;
  • Show after load: opacity: 1; visibility: visible;
  • Error fallback: Widget still appears with defaults if API fails

Benefits:

  • ✅ Professional appearance - no jarring flashes
  • ✅ Smooth 300ms fade-in animation
  • ✅ Users only see final/correct branding
  • ✅ Error resilient - works even if API fails
  • ✅ No breaking changes to functionality
